# 智能钱包与代付策略

这是一个在本机运行的智能钱包与代付策略。只管理代付费用的预留、结算与
退回，不执行任何真实转账；所有状态仅保留在同一次运行（同一 `Wallet`
实例）的内存中。

## 使用

```bash
go test ./...
```

## 能力概览

入口类型为 `wallet.Wallet`，通过 `wallet.New()` 创建。原有的
`wallet.Ready()` 公开入口保持不变。

- 账户：`CreateAccount` 创建带唯一编号和初始代付余额的账户；`Balance`
  同时返回可用余额 `Available` 与预留余额 `Reserved`。金额统一为最小
  货币单位的整数，初始余额不得为负，重复编号返回错误。
- 会话：`CreateSession` 为账户创建绑定设备、带到期时间的会话，
  `RevokeSession` 主动吊销。到期时刻及之后视为过期；不存在、所属账户
  不符、设备不符、已过期或已吊销的会话一律拒绝代付申请。吊销不影响
  已预留费用请求的结算或取消。
- 策略：`SavePolicy` 保存代付策略，明确出资账户、允许使用的账户、操作
  类型、收款方、`[StartsAt, EndsAt)` 时间窗（含开始、不含结束）、单次
  上限与多使用账户共享的累计上限。出资/使用账户必须存在、限额必须为
  正、开始必须早于结束，否则拒绝保存。
- 大额审批：策略可设置审批门槛 `ApprovalThreshold` 与最长等待时长
  `ApprovalWait`。门槛为零表示关闭；门槛为负、超过单次上限，或开启
  审批时等待时长不为正，均拒绝保存。未开启审批的策略沿用原有行为。
  申请通过会话、授权、余额与全部硬限额检查后，预估费用严格超过门槛
  的进入待审批，其余直接预留。待审批不冻结余额、不占用共享累计额度；
  期限取提交时刻加等待时长、策略结束时间、申请会话到期时间三者中的
  最早值，到期即过期。
- 审批：`Approve` / `Reject` 必须使用该策略出资账户绑定当前设备的
  有效会话；其他账户或无效会话返回无权审批，不改变请求。批准时再次
  检查出资余额与共享剩余额度，足够才一次性预留全部预估费用并转为
  已预留，不足时返回具体原因并保留待审批，期限内可再次批准。拒绝
  理由为空或全为空白时返回参数错误。申请会话被吊销时，仍在待审批
  的请求进入拒绝终态并说明原因；已预留的请求仍可结算或取消。
- 策略停用：`DeactivatePolicy` 由出资账户用绑定当前设备的有效会话，
  指定策略编号与停用理由（按去掉首尾空白后的内容保存与比较），立即
  停止该策略继续受理代付。会话不存在、不属于出资账户、设备不符、被
  吊销或已到期返回无权停用；编号或理由缺失、理由空白返回参数错误；
  策略不存在返回策略不存在。停用不可撤销，新保存的策略默认未停用，
  停用后的编号不能重新保存成新策略。查询策略可见停用状态、首次停用
  时间、执行账户与理由，原策略条件及累计金额仍可查询。再次停用仍须
  通过会话校验：理由相同返回首次结果，理由不同返回冲突，均不改写首次
  信息或增加账本记录。尚未开始或已经结束的策略也允许停用。停用时未到
  等待期限的待审批请求立即转为拒绝终态（拒绝信息说明策略被停用并包含
  理由，决定时间为停用时间），已到或超过等待期限的进入过期终态；两类
  处理都不冻结余额、不占用额度、不产生退款。已预留及各终态请求不改写，
  其他策略不受影响。停用后用有效会话提交新申请返回明确的策略已停用
  错误并留下拒绝原因；同号同内容的历史申请仍返回已有结果，同号不同
  内容仍返回冲突。账本新增 `LedgerPolicyDeactivation` 留痕，金额为
  零，关联出资账户与策略，与请求的拒绝、过期记录区分。
- 结算与取消：`Settle` 确认实际费用（允许为零、不得超过预估值），扣除
  实际费用并退回差额；超额或负数结算被拒绝且保留预留。`Cancel` 退回
  全部预留；待审批请求取消直接进入取消终态，不产生退款。已结算不能
  取消，已取消不能结算，结算只允许处理已预留请求。
- 预留超时：策略可设置最长预留时长 `ReservationTimeout`，零表示不启用
  超时（保持现有行为），负值保存时返回策略无效且不创建策略。直接受理
  的申请从受理时刻起算，待审批请求从批准成功时刻起算（等待审批的时间
  不计入；批准因余额或额度不足失败时不提前开始计时）。启用超时的已
  预留请求在截止时刻及之后进入独立的“预留超时”终态，与审批等待过期
  区分；超时退回全部预估费用，减少出资账户预留余额和该策略预留总额，
  不增加实际费用或已花费总额。释放时间记录截止时刻，即使过了很久才
  访问也不改成访问时刻。账户、余额、策略、请求及账本查询都反映查询
  时已到期预留的释放结果，调用者无须逐笔取消；新申请与批准检查资金
  和额度时也计入已到期预留的退回（包括同一出资账户在其他策略下的
  预留）。超时后非负实际费用的结算返回预留已超时错误，不能扣款；取消
  返回已有超时结果，不重复退回；同号同内容申请返回超时结果，同号不同
  内容返回冲突，重新发起必须换请求编号；重复批准不能恢复预留。账本为
  每次超时增加一条出资账户的全额退款和一条使用账户的零金额超时记录，
  均关联请求并说明原因，保留原预留和审批记录。会话到期或吊销、策略
  结束或停用都不提前缩短已预留请求的截止时间；截止前成功结算或取消
  的终态保持不变；并发结算、取消与超时处理只能有一个结果，退款只发生
  一次。
- 幂等：同一使用账户用相同请求编号重复申请，内容一致时返回已有结果、
  不重复预留，内容不同返回 `ErrConflict`；相同实际费用的重复结算、
  重复取消均不重复记账，不同实际费用返回冲突。已批准且处于预留或
  结算状态的请求重复批准只返回当前结果；重复拒绝且理由一致、重复
  取消均不重复留痕，拒绝理由不同返回冲突。已批准不能再拒绝，已拒绝、
  过期、取消或预留超时不能再批准；并发批准或拒绝以先成功的决定为准。
- 账本：`Ledger` / `AccountLedger` 查询预留、扣减、退回及拒绝记录，
  每条资金记录都带有关联请求编号与金额。新增待审批、批准、拒绝、
  取消、过期、策略停用及预留超时状态记录，不改变金额；策略停用记录
  关联出资账户与策略编号，其余状态记录关联使用账户与请求编号；批准
  带来的预留及后续扣减、退回继续进入原资金账本；预留超时给出资账户
  带来全额退款（`LedgerRefund`），给使用账户带来零金额超时记录
  （`LedgerReservationTimeout`）。

所有方法均可被多个 goroutine 并发调用：单次申请、批准、拒绝、停用、
结算或取消在内部原子完成，余额与共享额度不会超扣，同一请求只会产生
一个终态；停用与申请、审批竞争时以先完成的操作为准，策略停用时不
可能仍读到可批准的待审批请求。
