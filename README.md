# 智能钱包与代付策略

这是一个在本机运行的智能钱包与代付策略。只管理代付费用的预留、结算与
退回，不执行任何真实转账；所有状态仅保留在同一次运行（同一 `Wallet`
实例）的内存中。

## 使用

```bash
go test ./...
```

## 能力概览

入口类型为 `wallet.Wallet`，通过 `wallet.New()` 创建。原有的
`wallet.Ready()` 公开入口保持不变。

- 账户：`CreateAccount` 创建带唯一编号和初始代付余额的账户；`Balance`
  同时返回可用余额 `Available` 与预留余额 `Reserved`。金额统一为最小
  货币单位的整数，初始余额不得为负，重复编号返回错误。
- 会话：`CreateSession` 为账户创建绑定设备、带到期时间的会话，
  `RevokeSession` 主动吊销。到期时刻及之后视为过期；不存在、所属账户
  不符、设备不符、已过期或已吊销的会话一律拒绝代付申请。吊销不影响
  已预留费用请求的结算或取消。
- 策略：`SavePolicy` 保存代付策略，明确出资账户、允许使用的账户、操作
  类型、收款方、`[StartsAt, EndsAt)` 时间窗（含开始、不含结束）、单次
  上限与多使用账户共享的累计上限。出资/使用账户必须存在、限额必须为
  正、开始必须早于结束，否则拒绝保存。策略还可以通过 `ApprovalThreshold`
  开启大额审批：门槛为零表示关闭；为负、超过单次上限，或开启审批时
  `ApprovalWait` 不为正，均拒绝保存。
- 代付申请：`Apply` 校验会话与全部策略条件，预估费用必须为正。审批关闭
  或预估费用未严格超过门槛时，从出资账户可用余额预留预估费用（同时占用
  共享累计额度）；严格超过门槛的申请在通过会话、授权、余额和全部硬限额
  检查后进入待审批（`RequestPendingApproval`），此时不冻结余额、也不占用
  共享累计额度。没有匹配授权、超额或余额不足时默认拒绝，拒绝会在账本
  留下具体原因，不扣款。
- 大额审批：`Approve` / `Reject` 处理待审批请求，二者都必须使用策略出资
  账户绑定当前设备的有效会话，其他账户或无效会话返回
  `ErrApprovalUnauthorized` 且不改变请求；拒绝理由为空或全为空白返回
  `ErrInvalidArgument`。批准时再次检查出资余额与共享剩余额度，足够才一次
  性预留全部预估费用并转为已预留；不足返回具体原因并保留待审批，期限内
  可再次批准。待审批期限为提交时刻加等待时长、策略结束时间、申请会话
  到期时间三者的最早值：到达期限即进入过期终态（`RequestExpired`，查询时
  惰性生效），截止时刻及之后不能批准；申请会话在期限前被吊销时，仍在待
  审批的请求进入拒绝终态（`RequestRejected`）并说明原因，已批准并预留的
  请求仍可按原规则结算或取消。拒绝和取消待审批请求不产生退款。
- 结算与取消：`Settle` 只处理已预留请求，确认实际费用（允许为零、不得
  超过预估值），扣除实际费用并退回差额；超额或负数结算被拒绝且保留预留。
  `Cancel` 对已预留请求退回全部预留，对待审批请求只留下取消终态。已结算
  不能取消，已取消不能结算。
- 幂等：同一使用账户用相同请求编号重复申请，内容一致时返回已有结果、
  不重复预留（待审批或终态请求都不会被重新创建），内容不同返回
  `ErrConflict`；相同实际费用的重复结算、重复取消、相同理由的重复拒绝、
  已获批请求的重复批准均不重复记账或留痕，不同实际费用或不同拒绝理由
  返回冲突。
- 并发：已批准不能再拒绝，已拒绝、过期或取消不能再批准；并发批准或拒绝
  以先成功的决定为准；取消先完成则批准失败，批准先完成则取消按已预留
  规则退回。
- 账本：`Ledger` / `AccountLedger` 查询预留、扣减、退回、拒绝以及待审批、
  批准、拒绝、取消、过期五类状态留痕；每条记录都关联使用账户与请求编号，
  状态留痕金额为零，批准带来的预留及后续扣减、退回继续进入原资金账本。
  `RequestView` 可查看等待期限、审批决定时间、审批账户与拒绝原因。

所有方法均可被多个 goroutine 并发调用：单次申请、结算或取消在内部
原子完成，余额与共享额度不会超扣，同一请求只会产生一个终态。
